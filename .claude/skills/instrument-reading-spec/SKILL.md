# 계측기 읽기 명세 작성

## 왜 명세를 먼저 만드는가
UI 코드가 눈금 규칙을 잘못 알면 학생이 틀린 정답을 학습한다. 규칙을 한 곳(명세)에 고정하고, 개발과 QA가 같은 문서를 기준으로 삼게 한다.

## 절차
1. 대상 계측기의 `references/{instrument}.md`를 읽는다. 파일명: `vernier-caliper`, `outside-micrometer`, `inside-micrometer`, `dial-gauge`, `height-gauge`.
2. 아래 형식으로 `_workspace/01_spec_{instrument}.md`를 쓴다.
   - 측정 범위 / 분해능 / 선택 옵션과 기본값
   - 움직이는 부품과 이동 방식(드래그 축, 스냅 단위)
   - 상태 변수(정수 단위) → 정답 계산식
   - 무작위 문제 범위 (분해능 배수만 출제, 경계값은 포함)
   - 정답 설명문 템플릿
3. 참조 문서에 없는 규칙이나 수업 방식에 따라 갈리는 점은 "확인 필요"로 올린다. 추측하지 않는다.

## 공통 원칙
- 정답은 정수 단위(예: 1/1000 mm)로 계산하고 표시 때만 소수로 바꾼다. 0.1+0.2 같은 오차가 정답에 섞이면 안 되기 때문이다.
- 읽기 연습이므로 "어떤 눈금을 어떻게 더했는지" 설명문을 정답과 함께 보여준다.
