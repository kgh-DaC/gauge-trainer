# 눈금읽기 도구 제작 오케스트레이터

**실행 모드:** 서브에이전트 위임 + 파일 전달(`_workspace/`). 계측기 5종이 서로 독립적이라 병렬로 처리하고, 에이전트끼리 대화할 필요가 없어서다.

## 0단계: 맥락 확인
- `_workspace/`가 없으면 처음부터.
- 있고 "특정 계측기만 고쳐줘" → 해당 계측기만 2~3단계 재실행.
- 있고 새 계측기/옵션 추가 → 기존 폴더 유지, 해당 계측기만 1~3단계 후 4단계 재통합.
- 전체 새로 요청 → `_workspace/`를 `_workspace_{YYYYMMDD-HHMM}/`로 옮기고 시작.

## 1단계: 명세 (gauge-spec-writer)
계측기당 한 번씩 병렬 호출(`subagent_type: "gauge-spec-writer"`, 한 메시지에 5개). 결과: `_workspace/01_spec_{id}.md`.
- id: `vernier`, `outside-mic`, `inside-mic`, `dial`, `height`
- 각 명세의 "확인 필요" 항목을 모아 사용자에게 한 번에 묻는다(특히 내측마이크로미터 종류). 답을 받은 뒤 2단계로 간다.

## 2단계: 위젯 개발 (gauge-ui-builder)
계측기당 한 번씩 병렬 호출. 입력은 명세 경로만 전달한다. 결과: `_workspace/02_widget_{id}.html`.

## 3단계: QA (gauge-qa)
위젯별로 병렬 호출(모든 도구를 쓸 수 있는 유형). FAIL이면 보고서를 `gauge-ui-builder`에 돌려주고 해당 위젯만 재작업 → 재QA. 최대 2회 반복 후에도 FAIL이면 사용자에게 현황 보고.

## 4단계: 통합
`_workspace/02_widget_*.html`을 합쳐 탭형 단일 페이지 `output/gauge-trainer.html`을 만든다. 각 위젯의 `GaugeWidget` 인터페이스를 이용한다(IIFE라서 충돌이 없다). 탭은 5개, 첫 화면은 버니어캘리퍼스. 통합 후 탭 전환 시 정답 패널이 닫히는지 확인한다. 개별 위젯 파일은 `output/`에 따로 내보내지 않고 통합본 1개만 둔다.

## 5단계: 노션 연결
노션 페이지에는 `/embed`(또는 `/임베드`)로 URL을 붙여넣어야 하므로 HTML이 공개 URL에 있어야 한다. 제안 순서:
1. Artifact로 게시해 URL을 얻고 노션에서 임베드를 시도한다. 임베드가 막히면
2. GitHub Pages / Netlify Drop / Cloudflare Pages 등 정적 호스팅에 올린 URL을 쓴다.
외부 서비스에 게시하는 행위는 사용자 확인 후 진행한다.

## 오류 처리
- 에이전트 실패 → 1회 재시도, 재실패 시 해당 계측기를 빼고 진행하고 최종 보고에 누락을 적는다.
- 명세 충돌(수업 방식 불명) → 추측 금지, 사용자에게 질문.

## 테스트 시나리오
- 정상: "버니어캘리퍼스만 먼저 만들어줘" → vernier 1~3단계 → `output/gauge-trainer.html`(버니어 탭) → 23.35mm 샘플에서 설명문 "본척 23mm + 부척 7번째 선 × 0.05 = 23.35mm" 확인.
- 오류: 다이얼게이지 QA에서 바늘이 99→100 경계에서 작은 바늘 오독 → FAIL 보고 → 해당 위젯만 재작업 후 재QA.
