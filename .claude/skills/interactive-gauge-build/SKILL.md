# 인터랙티브 계측기 위젯 구현

## 목표
학생이 직접 눈금을 움직이고 읽어본 뒤 "정답확인"으로 자기 읽기를 검증한다. 노션에 임베드되므로 파일 하나로 완결되어야 한다.

## 구현 규칙
1. `assets/widget-skeleton.html`을 복사해 시작한다. 드래그, 정답 패널, 새 문제 버튼, 공통 인터페이스가 들어 있다.
2. 외부 의존성 없음(CDN·이미지·폰트 파일 금지). 노션 임베드 환경에서 막히는 일이 없도록 한다.
3. SVG는 `viewBox`로 반응형. 휴대폰 폭에서도 눈금이 읽혀야 한다. 눈금이 너무 촘촘하면 "확대" 토글 또는 확대 창을 제공한다(부척 일치선을 눈으로 구분해야 하는 연습이기 때문).
4. 입력은 Pointer Events(`pointerdown/move/up` + `setPointerCapture`)로 처리하고 `touch-action: none`을 지정한다.
5. 상태는 정수 단위 하나(명세의 상태변수)로 유지하고, 그림은 상태에서만 그린다. 그림과 정답이 같은 변수에서 나오므로 서로 어긋나지 않는다.
6. 정답은 처음에 숨긴다. "정답확인"은 값 + 계산 설명문을 표시한다. 같은 위치에서 다시 누르면 토글한다. 정답이 열린 상태에서 슬라이드를 움직이면 정답 패널을 닫는다(오래된 정답이 남아 오해를 만들지 않도록).
7. "새 문제"는 명세의 출제 범위에서 무작위 위치로 초기화하고 정답 패널을 닫는다. 경계값 풀에서 20% 확률로 출제한다.
8. 선택 옵션(1/20↔1/50 등)은 위젯 상단 토글로 제공하되 기본값은 명세를 따른다.
9. 한국어 UI. 단위(mm)를 정답에 항상 표시. 소수 자릿수는 분해능에 맞춘다(0.05→2자리, 0.01→2자리, 0.001→3자리).

## 공통 인터페이스
`window.GaugeWidget = { id, title, mount(el), newProblem(), reveal() }` — 병합 단계에서 탭 UI가 이 객체를 호출한다. 한 파일 안에서 전역 이름 충돌을 피하려면 모든 코드를 IIFE로 감싸고 DOM id에 계측기 id 접두어를 붙인다.

## 완료 전 자기 점검
- 최소/최대 위치에서 정답이 범위를 벗어나지 않는가
- 드래그 중 포인터가 요소 밖으로 나가도 계속 따라오는가
- 정답을 연달아 확인/새 문제를 눌러도 상태가 꼬이지 않는가
