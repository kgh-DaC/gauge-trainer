# 위젯 QA 절차

## 왜 실행 검증인가
눈금 읽기 도구는 "그림"과 "정답"이 따로 놀면 학생에게 잘못된 지식을 준다. 코드를 읽는 것만으로는 SVG 좌표와 계산식의 불일치를 놓치기 쉽다.

## 절차
1. 명세(`01_spec_*.md`)의 상태변수/계산식을 손계산 가능한 샘플로 만든다. 샘플 최소 8개: 최소값, 최대값, 명세의 경계값 전부, 임의 3개.
2. **계산 검증**: 위젯 JS의 `answer()`를 Node 또는 브라우저에서 직접 호출해 기대값과 비교한다. 위젯 스크립트를 jsdom에 로드하거나 `javascript_tool`로 `GaugeWidget`을 조작한다.
3. **그림 검증**: 가능하면 브라우저로 샘플 위치를 렌더링해 스크린샷으로 눈금 일치(예: 부척 n번째 선이 실제로 본척 선과 겹치는지)를 눈으로 확인한다. 브라우저가 없으면 SVG 요소의 좌표를 계산식과 대조한다.
4. **동작 검증**: 드래그(pointer 이벤트) → 정답 패널 닫힘, 정답확인 토글, 새 문제 초기화, 범위 클램프.
5. 결과를 `_workspace/03_qa_{instrument}.md`에 표로 기록한다: 항목 / 위치 / 기대값 / 실제값 / 판정.

## 판정
- 하나라도 불일치하면 FAIL. 수정은 직접 하지 않고 재현 조건과 함께 `gauge-ui-builder`에게 돌려준다.
- 부동소수점 문제(예: 23.349999)가 표시에 나타나면 FAIL.
